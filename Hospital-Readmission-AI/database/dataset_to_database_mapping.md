# Dataset to Database Mapping

How `diabetic_data.csv` + `IDS_mapping.csv` (Diabetes 130-US Hospitals, 1999-2008)
are stored in SQL Server. Owner: Member 4 (ETL + Database).

The table below is **generated from `etl/cleaning.py` -> `COLUMN_SPEC`**, the single
definition used by cleaning, validation and loading. `etl/tests/test_etl.py` checks
that `database/schema.sql` and `migrations/001` match it exactly (type, NULL rule,
CHECK value lists).

## Load flow

```
diabetic_data.csv (50 cols, 101,766 rows) --clean--> diabetic_data_cleaned.csv (59 cols, 101,766 rows)
IDS_mapping.csv (3 sections)               --------> AdmissionTypes / DischargeDispositions / AdmissionSources
```

| Order | Table | Rows (full file) | Key and relationships |
|---|---|---|---|
| 1 | AdmissionTypes / DischargeDispositions / AdmissionSources | 8 / 30 / 25 | original IDs from IDS_mapping.csv (PK) |
| 2 | Uploads | 1 per ETL run | UploadId (identity) |
| 3 | Patients | 71,518 | PatientId (identity); `ExternalPatientId` = patient_nbr (unique) |
| 4 | Admissions | 101,766 | AdmissionId (identity); `ExternalAdmissionId` = encounter_id (unique); FK PatientId, UploadId, 3 lookup IDs |
| 5 | AdmissionMedications | 101,766 | AdmissionId = PK and FK (1:1 with Admissions) |
| 6 | DataQualityLogs | ~20 per run | FK UploadId; one row per validation finding |

`PatientId` and `AdmissionId` are generated by SQL Server. The loader links rows by
looking them up from `ExternalPatientId` / `ExternalAdmissionId` after each insert.
A patient with several stays has one Patients row and several Admissions rows
(16,773 patients have more than one admission).

## Database columns that are not filled from the dataset

| Column | Value | Why |
|---|---|---|
| Admissions.AdmissionDate, DischargeDate | NULL | the source has no dates; dates are never generated |
| Patients.DateOfBirth | NULL | not in the source; never generated |
| Patients.Age | NULL | the source only has 10-year bands, stored per stay in Admissions.AgeGroup |
| Patients.InsuranceType | NULL | payer can change between stays; stored per stay in Admissions.PayerCode |
| Admissions.PatientId, UploadId | set by the loader | looked up after inserting Patients / Uploads |

## Patient-level vs admission-level demographics

* `Admissions.RaceAtAdmission` / `GenderAtAdmission` keep the value recorded for each stay
  (`?` -> NULL; `Unknown/Invalid` kept as is).
* `Patients.Race` / `Gender` are filled only when all known values of that patient agree;
  otherwise NULL and `Patients.HasDemographicConflict = 1` (126 patients). Nothing is overwritten.

## Lookup tables

`Description` keeps the IDS_mapping.csv text (surrounding spaces trimmed only).
`IsPlaceholder = 1` marks descriptions that are not real categories
(`NULL`, `Not Mapped`, `Unknown/Invalid`, `Not Available`); for those IDs the
admission's text column (`AdmissionType`, `DischargeDisposition`, `AdmissionSource`)
is NULL while the ID column keeps the original code.
